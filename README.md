# Automated-Pages-Generator

基于 Electron / Chromium 的独立 Windows 桌面工作区。保留原 Shopify Page Studio 的输入字段、七个生成页面 + 固定 Contact Us、业务规则与 Pages / Menus XLSX 列顺序。原项目未被修改或迁移删除。

0.1.2 将浏览器加载与自动化配置状态分别显示，列出缺失规则和未发送任务数。修复空输入框仅显示麦克风时无法进入填入步骤，以及恢复生成误要求发送按钮的问题。填入后等待发送按钮可用再继续，超时不会发送。新增用户点击的「导出接入诊断」，仅导出控件结构、规则是否配置及任务状态计数，不含对话正文、输入值、账号、Cookie 或登录存储。请将诊断文件交给开发者据实适配，而非猜测选择器。已登录并不表示自动化规则已接通。

## 当前状态

当前仍为需要现场适配的实验版本。初版开发时访问豆包报 `ERR_CONNECTION_CLOSED`；用户随后提供的截图已显示豆包成功加载并登录，但本地自动化规则仍为空，一条任务尚未发送。程序没有预置猜测的豆包选择器。请先点击「导出接入诊断」，将得到的 JSON 文件提供给开发者，按真实页面结构补齐适配。定位配置与真实联网、长回答、验证码、暂停恢复仍需用户现场验证。

## 安装与运行

Windows x64：解压构建包，运行 `Automated-Pages-Generator.exe`。无需 DSH 或 API Key。源码运行（Node.js 22.12+）：

```powershell
npm ci
npm test
npm start
```

构建：`npm run build`。输出 `build/<版本>/Automated-Pages-Generator-win32-x64/`，分发时必须压缩整个目录，不能仅发送 exe。使用 `python scripts/archive.py` 可生成完整压缩包与校验文件。未进行代码签名，首次运行可能显示发布者未知。

## 首次登录与定位

右侧为实际豆包网站，在其中手动登录或手动选择/创建会话。登录 Cookie 留在 Electron 当前用户 userData 的持久分区中，不上传仓库。此版没有自动填密码功能。第三方登录跳转和新窗口默认受限；需要第三方身份服务时应先审查并增加明确允许的域名，不能关闭浏览器安全隔离。

首次使用需在真实页面右键标定元素，也可以在「网页定位规则」编辑 CSS 规则。全部规则集中保存：

|规则|含义|
|---|---|
|input / send|唯一可见编辑框 / 发送按钮|
|user / answer|所有用户消息容器 / 所有助手回答容器；必须是互不嵌套的消息级容器|
|body / done|相对于 answer 的正文 / 此回答完成后才出现的控制元素|
|stop|生成中的停止按钮|
|blocker|验证码、登录失效、账号异常、额度限制提示；必须覆盖现场实际状态|
|search / searchEnabled|联网开关 / 只有已启用时才匹配的状态指示器|
|expand|answer 内展开完整正文的按钮（可选）|

右键工具生成的是所点元素路径，需对重复消息去掉特定 ID 和 nth 路径并在现场确认，不可将整个页面当回答。校验按钮仅检查当前规则可用性，不代表已验证所有异常状态。建议先用低风险测试任务确认实际消息容器、完成信号与异常匹配。手动新建会话后开始任务；运行中不要手动向同一会话发送其他消息。

## 批量、字段与导出

填写参考标题、内容和折扣（1–100），邮箱与日期选填。编辑提示词，按需勾选联网后加入队列，可连续加入多个任务，默认串行。点击「检查并继续」。提示词含任务 UUID，与发送后的对应用户消息绑定，只读取其后唯一助手回答内的正文，不取整个页面或最后一条历史回答。

完成识别要求对应回答完成控件存在、停止控件消失、正文稳定至少 2.5 秒且无折叠。15 分钟仍未完成则暂停，不凭固定等待时间导出。DOM 虚拟化导致无法找到绑定消息时停止推进，保留已采集文本；不会以截断回答当成功。此版尚未实现跨虚拟化片段的可靠拼接，长回答实测前不要用于无人值守批量生产。

结果只按 JSON 解析，沿用业务规则校验，失败最多一次自动格式修复，再失败标为「校验失败」。通过后自动本地导出真实 XLSX，固定八页，默认 Published=true。无需让模型生成文件。每份文件以任务、修订和内容哈希命名，不覆盖；同一任务修订及内容哈希不重复导出，即使导出后程序异常退出也会核对原文件而非重复创建。导出记录保存在本机。

点击已完成任务，结果 JSON 会加载到编辑框；可预览源码并编辑。保存编辑会重新校验并导出新修订。只勾选某字段生成时，用当前编辑框的完整合法结果作基准，模型只能返回选中字段；未选字段和手动修改由程序保留。页面 title 沿用原项目固定标题规则，不能改成任意 SEO 标题；SEO 位于现有 marketing.seo。没有增加业务字段。

联网任务只有实际已启用指示器出现才发送。回答中的链接作为来源记录保存，不把开启开关或模型普通回答标为「已核实」；来源真实性仍需核对。需要引用时提示词要求沿用 marketing.review_notes 存放可核对 URL。

## 暂停与恢复

验证码、登录、额度等由 blocker 规则匹配，或定位不唯一/超时，队列暂停并显示错误。用户手动处理后点继续，重新检查页面状态，保持原任务绑定不重新发送。取消不会重发或导出该任务，网页生成若仍在继续需手动停止。进程重启时执行中任务置为待人工处理；若网页不能恢复原绑定，请取消并手动检查结果，而非重复提交。

本机数据路径显示在界面底部，一般为 `%APPDATA%/automated-pages-generator`，包含浏览器登录状态、任务、规则和导出文件。输入内容与提示词会发送至豆包，勿填入不应发送的私密材料。退出程序后备份该目录可以保留任务；卸载只删除应用目录，保留数据。若要清除登录和所有历史，请退出后自行删除该数据目录。

## 验证边界

自动化测试使用明确的合成测试数据，只验证本地字段合并、拒绝非法数据和确定性导出，不代表豆包生成通过。真实网页登录、联网、长回答、title生成、验证码及额度暂停恢复：当前均未验证，网络访问为真实阻塞。详见 `docs/verification.md`。
