# Automated-Pages-Generator

基于 Electron / Chromium 的 Windows 桌面工作区。保留 Shopify Page Studio 原有输入、七个生成页面 + 固定 Contact Us、字段规则和 Pages / Menus XLSX 导出。原项目保持独立。

**0.1.8 是后台连接实验版，业务队列尚未接通后台接口。** 根据用户提供的真实协议实现了消息绑定和流式回答解析，并新增一次后台调用测试。测试只有在三轮手动校准通过、请求参数符合实测关系且入口未带旧签名时才允许发送。失败停止，不自动重试。

## 安装与运行

1. 关闭旧版，完整解压 `Automated-Pages-Generator-0.1.8-win32-x64-experimental.zip`。
2. 运行解压目录中的 `Automated-Pages-Generator.exe`，确认左上角 `v0.1.8`。不要只复制 exe。
3. 无需 DSH、API Key 或单独安装浏览器。既有本地任务和登录分区继续使用，不删除数据。

本地构建入口：`build/0.1.8/Automated-Pages-Generator-win32-x64/Automated-Pages-Generator.exe`。压缩包及 `SHA256SUMS.txt` 在 `build/`。Windows 可执行 `Get-FileHash .\Automated-Pages-Generator-0.1.8-win32-x64-experimental.zip -Algorithm SHA256` 后与校验文件比较。程序尚未进行代码签名。

源码运行需要 Node.js 22.12+：

```powershell
npm ci
npm test
npm start
```

构建用 `npm run build`；打包用 `python scripts/archive.py`，需要 Python 3。输出完整 Chromium 目录与 ZIP。开发者遵从用户要求，不运行或操作实际窗口，页面验收由用户完成。

## 当前需要你操作的测试

旧诊断有意删除了参数值，不能从文件恢复有效请求模板。新版需要在当前网页内存中重新学习三次真实请求；参数、请求头和签名均不写文件。

1. 在右侧手动登录豆包，手动新建一个普通测试会话。点击左侧「开始后台校准」。该按钮只安装观察器，不发送消息。
2. 点击「复制测试1」，在右侧手动粘贴发送，等回答结束。
3. 在同一会话中发送「复制测试2」，再次等回答结束；再发送「复制测试3」并等回答结束。不要同时发送其他内容或切换会话。
4. 显示「可以测试」后，点击「测试一次后台调用」。程序借用当前网页已有的 fetch 处理函数发送第四条短校准消息，无需点击网页输入框。仅发一次，不重试。
5. 点击「结束并保存报告」，把 `doubao-backend-*.json` 的完整路径发给开发者。报告保存在 `%APPDATA%/automated-pages-generator/diagnostics/`，无需发送账号或浏览器目录。

手动校准最多4分钟，后台测试最多60秒，总观察最多5分钟。只有第四条回答与随机标记精确一致、消息及结束链路完整、并观察到实际请求使用新的签名，才显示后台连接测试通过。HTTP200、网页有回答或报告保存成功都不单独算通过。

如果提示签名已在入口生成、参数关系不支持、登录/验证码/额度异常或结构变化，测试停止并保留明确原因。请结束保存报告，不重复点击发送或换账号规避限制。人工处理后可以开始新的校准，但旧测试不会自动重放。测试通过也仅代表本次短消息连接有效，不能代表联网、长回答和业务 XLSX 已通过。

## 实现与数据边界

真实证据确认端点为 `POST https://www.doubao.com/chat/completion`，请求间 `a_bogus` 会变化。程序不猜签名算法、不重放最终签名 URL、不调用猜测的网站内部函数。只在当前页面标准 `window.fetch` 调用边界观察三条合成请求：入口已包含签名则阻止后台测试；入口未签名时，尝试交给网站原有 fetch 处理函数，实际是否重新签名由网络观察确认。

请求模板仅保留在当前网页闭包内存，停止、刷新或退出即清除。Cookie 由 Chromium 当前用户的持久分区管理，代码不读取 Cookie、密码或登录存储。诊断不保存 URL 查询值、请求头值、原始标识符、请求模板或回答正文，也不自动上传。网页保持浏览器隔离，无 Node 或本地 IPC 权限。

解析将本次 local message → ACK question → assistant reply 逐级绑定。正文取首段、匹配块片段和同一响应的 delta；用户回显、TTS 与建议不混入正文。必须同时满足正文块、消息、回答、最终事件和干净 HTTP 结束。校准标记精确匹配后才接受对应 patch 控制组合；未知组合中止。当前只支持实测的单文本块普通对话。

API 使用方式依据 [Electron webContents](https://www.electronjs.org/docs/latest/api/web-contents) 和 [浏览器 Fetch API](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch)；这些文档只证明标准桥接机制，不证明豆包必然支持后台签名。

原「协议采集」与页面结构诊断保留在折叠的进阶区域，只有需要更多诊断时使用；新后台测试不要求八项 DOM 规则。需要联网的任务仍未开放后台验证，普通回答不能标为已联网核实。

## 旧版 DOM 路径：仅在规则适配后使用

以下为保留的 DOM 自动化配置说明，不是本次协议采集的前置步骤。需要继续使用该路径时，在真实页面右键标定元素，也可以在「网页定位规则」编辑 CSS 规则。全部规则集中保存：

|规则|含义|
|---|---|
|input / send|唯一可见编辑框 / 发送按钮|
|user / answer|所有用户消息容器 / 所有助手回答容器；必须是互不嵌套的消息级容器|
|body / done|相对于 answer 的正文 / 此回答完成后才出现的控制元素|
|stop|生成中的停止按钮|
|blocker|验证码、登录失效、账号异常、额度限制提示；必须覆盖现场实际状态|
|search / searchEnabled|联网开关 / 只有已启用时才匹配的状态指示器|
|expand|answer 内展开完整正文的按钮（可选）|

右键工具生成的是所点元素路径，需对重复消息去掉特定 ID 和 nth 路径并在现场确认，不可将整个页面当回答。校验按钮仅检查当前规则可用性，不代表已验证所有异常状态。建议先用低风险测试任务确认实际消息容器、完成信号与异常匹配。手动新建会话后开始任务；运行中不要手动向同一会话发送其他消息。

## 批量、字段与导出

以下是现有 DOM 路径的操作方式，需先完成实际规则适配和现场验证。后台路径目前只开放单次合成消息测试，不发送或导出业务内容。

填写参考标题、内容和折扣（1–100），邮箱与日期选填。编辑提示词，按需勾选联网后加入队列，可连续加入多个任务，默认串行。点击「检查并继续」。提示词含任务 UUID，与发送后的对应用户消息绑定，只读取其后唯一助手回答内的正文，不取整个页面或最后一条历史回答。

完成识别要求对应回答完成控件存在、停止控件消失、正文稳定至少 2.5 秒且无折叠。15 分钟仍未完成则暂停，不凭固定等待时间导出。DOM 虚拟化导致无法找到绑定消息时停止推进，保留已采集文本；不会以截断回答当成功。此版尚未实现跨虚拟化片段的可靠拼接，长回答实测前不要用于无人值守批量生产。

结果只按 JSON 解析，沿用业务规则校验，失败最多一次自动格式修复，再失败标为「校验失败」。通过后自动本地导出真实 XLSX，固定八页，默认 Published=true。无需让模型生成文件。每份文件以任务、修订和内容哈希命名，不覆盖；同一任务修订及内容哈希不重复导出，即使导出后程序异常退出也会核对原文件而非重复创建。导出记录保存在本机。

点击已完成任务，结果 JSON 会加载到编辑框；可预览源码并编辑。保存编辑会重新校验并导出新修订。只勾选某字段生成时，用当前编辑框的完整合法结果作基准，模型只能返回选中字段；未选字段和手动修改由程序保留。页面 title 沿用原项目固定标题规则，不能改成任意 SEO 标题；SEO 位于现有 marketing.seo。没有增加业务字段。

联网任务只有实际已启用指示器出现才发送。回答中的链接作为来源记录保存，不把开启开关或模型普通回答标为「已核实」；来源真实性仍需核对。需要引用时提示词要求沿用 marketing.review_notes 存放可核对 URL。

## 暂停与恢复

验证码、登录、额度等由 blocker 规则匹配，或定位不唯一/超时，队列暂停并显示错误。用户手动处理后点继续，重新检查页面状态，保持原任务绑定不重新发送。取消不会重发或导出该任务，网页生成若仍在继续需手动停止。进程重启时执行中任务置为待人工处理；若网页不能恢复原绑定，请取消并手动检查结果，而非重复提交。

本机数据路径显示在界面底部，一般为 `%APPDATA%/automated-pages-generator`，包含浏览器登录状态、任务、规则和导出文件。输入内容与提示词会发送至豆包，勿填入不应发送的私密材料。退出程序后备份该目录可以保留任务；卸载只删除应用目录，保留数据。若要清除登录和所有历史，请退出后自行删除该数据目录。

## 验证边界

用户提供的 0.1.4 诊断包含两轮真实请求、41 个有序 SSE 事件及无截断 HTTP 结束。请求与回答绑定、三类正文位置、多个结束阶段已有证据；追加语义、动态参数和后台调用仍须当前网页运行时精确校准。0.1.8 的单元测试是合成数据，不能代替账号实测。后台业务队列、联网搜索、长正文、title/其他字段生成及登录异常恢复尚未完成真实验收。详见 [验证记录](docs/verification.md) 与 [用户验收步骤](docs/manual-test.md)。

## 0.1.8 消息序号校准

0.1.7的用户实测已通过两条短回答的完整解析，但尚未发送后台测试，原因是请求last_message_index不等于已观察的问答序号。0.1.8新增第三条手动校准，以连续两次实测转换检查固定值或与问答序号的固定差值；候选必须对下一序号给出同一结果，否则停止。不是硬编码加1。报告只记录0至1000000范围内的序号数值及关系，不记录消息ID或凭据。每次只允许一次后台短消息测试，业务队列仍未接通。
