# Automated Pages Generator

Electron / Chromium Windows 桌面工作区：用户手动登录豆包，校准后通过当前网页的 fetch 通道生成 Shopify 页面及首页 / SEO 文案，无需 API Key。

## v0.2.1 安装

1. 关闭旧版，完整解压 `Automated-Pages-Generator-0.2.1-win32-x64-experimental.zip`。
2. 打开解压后 `Automated-Pages-Generator-win32-x64` 文件夹中的 `Automated-Pages-Generator.exe`，确认左上角 **v0.2.1**。不要只复制 EXE。
3. 旧任务、导出记录及登录分区继续使用 `%APPDATA%/automated-pages-generator/`。无需 DSH 或额外安装浏览器。程序尚未代码签名。

本地入口：`build/0.2.1/Automated-Pages-Generator-win32-x64/Automated-Pages-Generator.exe`。压缩包与 `SHA256SUMS.txt` 位于 `build/`。

```powershell
Get-FileHash .\Automated-Pages-Generator-0.2.1-win32-x64-experimental.zip -Algorithm SHA256
```

将结果与校验文件比对后使用。卸载时关闭程序并移除解压目录即可；用户数据默认保留。需要彻底清除时自行备份后移除上述 AppData 目录。

## 登录与后台连接

1. 在右侧手动登录，新建普通会话，点击「开始后台校准」。
2. 依次复制并手动发送测试1、测试2、测试3，每次等待完整回答，保持同一会话。
3. 点击「测试一次后台调用」。只有完整回答精确匹配且实际网络请求签名为新签名，才允许启动队列。
4. **测试通过后保持连接，不要点击断开。** 连接仅驻留当前页面内存，刷新、重启、导航或断开都会使其失效。登录状态仍保留在本机。

手动校准最多4分钟，短消息测试最多60秒。连接通过后取消校准期限，单条业务任务最多15分钟，每个连接最多1000次业务请求。没有验证码绕过或无限重试。

## 批量生成、字段重生成与自动导出

- 填写参考标题、内容、折扣。邮箱和日期为空时不编造。可修改提示词。
- 不选字段则生成整条数据。反复点击「加入串行队列」可加入不同输入的多条任务；点击「启动 / 继续后台队列」按顺序处理。
- 点击已有任务载入结果，在 JSON 编辑框中修改。需要单字段或选中字段生成时，勾选对应路径再加入队列，使用当前编辑框内容作为基准。未选字段及手工修改原样保留。
- 原业务规则保持不变：七个模型生成页面加固定 Contact Us；页面标题为既定名称。可变标题包含 `marketing.hero.title`；五组 SEO 的 title / description 通过 `marketing.seo` 整组生成。
- 回答与本次用户消息和助手消息绑定，流式显示正文；结束信号齐全、HTTP 流结束、唯一请求和新签名检查通过后才进入 JSON 校验。
- 检查字段、类型、条数、HTML 安全规则、正文长度等。仅完整回答的格式 / 字段错误允许自动修复一次，仍不通过标为「校验失败」，不导出。网络或协议失败不会当成格式错误重发。
- 校验通过自动导出真正的 `.xlsx`，沿用 **Pages / Menus** 的列名、顺序与八个可见页面。首页 / SEO 文案保存在本地任务 JSON 中供预览编辑；原 XLSX 模板不包含这些营销字段，不会把它们冒充 Shopify 页面 SEO 导入列。
- 同任务、同修订、同内容不会重复导出；保存编辑产生新修订文件，不覆盖旧文件。「打开导出目录」查看结果。

## 暂停、取消及恢复

「暂停队列」阻止后续发送，当前回答继续收集在内存；点击继续读取原绑定，不重发。取消当前请求会中止本地读取并使连接失效，需重新校准再继续剩余任务；取消排队任务不影响其他任务。

登录、验证码、额度、签名、协议或连接异常会暂停。人工处理后先断开并重新校准。状态不明且绑定旧连接的任务保留为「待人工处理」，不会自动重新提交；核对网页后自行取消，再明确创建新任务。重启时不会恢复旧网页内存请求。已经完成的任务不会再次发送。

**后台联网搜索能力尚未验证。** 勾选要求联网的任务在发送前暂停，明确提示不支持，不将普通回答标成已联网核实。长文、多块内容或不同结束控制若超出当前解析规则也会暂停，不接受不完整数据。

## 验证状态

用户提供的 v0.1.9 实际报告已证明三轮手动校准及第四条后台短消息成功。v0.2.1 的代码回归使用离线合成协议与任务，不登录或控制屏幕，不代表豆包业务验收通过。

本版需用户实测：完整页面长 JSON、title / SEO 选中字段、连续批量调用、暂停恢复、一次修复及真实生成 XLSX。详见 `docs/manual-test.md` 和 `docs/verification.md`。当前沿用已经接受的请求游标值，不猜测递增公式；连续业务请求是否兼容仍待实际验证。

## 隐私与诊断

请求模板、请求头和签名仅留内存。Cookie 由 Chromium 当前用户分区管理，不读取或导出密码。业务输入 / 结果写入本机 state.json；脱敏诊断不保存正文、请求 URL 查询值或头值，不自动上传。用完点击「断开并保存报告」，报告路径显示在界面中。不要提交 AppData 用户数据、诊断或浏览器目录。

进阶 DOM 定位和旧协议采集保留作诊断，业务队列使用后台通道，不要求 DOM 规则。原项目目录保持独立。

## 开发与打包

Node.js 22.12+、Python 3：

```powershell
npm ci
npm test
npm start
npm run build
python scripts/archive.py
```

本轮实际执行无进程隔离的等价测试命令 `node --experimental-test-isolation=none --test test/*.test.mjs`、`npm run build` 和打包脚本。未运行 `npm start` 或操作真实窗口。构建可通过 `ELECTRON_ZIP_DIR` 指向已有 Electron ZIP 缓存。
