# 由使用者执行的现场验收

不要在聊天中发送密码、Cookie 或完整浏览器数据。以下均尚未验证，请逐项记录通过/失败、错误信息、任务 ID；必要时只截取不含账户信息的区域。

0.1.2：若顶部显示「自动化尚未接通」，先点击「导出接入诊断」，把显示路径的 JSON 文件交给开发者。它仅记录控件结构，不记录对话正文、账号或登录凭据。无需重复加入任务或重复登录。下列自动生成验收须在实际定位规则适配完成后执行。

1. 解压并运行 exe。左侧输入/队列/结果出现，右侧豆包可交互；在右侧手动登录。退出再运行，确认登录仍有效。
2. 手动创建新会话，发送普通测试消息，等完整结束。根据 README 标定 input/send/user/answer/body/done/stop/blocker。重复容器采用通用规则，body/done 使用 answer 内相对规则。不存在的状态（验证码/额度）不要猜测选择器；在出现时手动确认并补齐 blocker。
3. 填写合成参考信息、折扣20，加入整条数据任务，点击检查并继续。确认网页只发送一次，任务标识一致，流式区域只显示对应回答。应得到七个生成页面和固定 Contact Us，About Us 至少3000词。
4. 检查长回答：滚动页面使旧消息离开可视区，再滚回，展开折叠。对照豆包复制出的完整回答与任务文本，不能缺尾或混入旧回答。当前虚拟化跨片段拼接未实现，无法绑定时应暂停/超时，不能导出成功。
5. 联网：标定真实 search/searchEnabled，勾选联网，选低风险公开资料任务。页面必须显示联网启用；保留实际来源 URL 并人工核对。关闭或删除联网状态规则时应拒绝发送，不得显示已联网核实。
6. 单字段：完成一条任务后点击它，在结果框修改 marketing.hero.description 为人工文字；只勾选 marketing.hero.title，加入任务。结果 title 更新，其余字段与手工描述必须逐字不变。页面 title 必须保持既有固定页面名。
7. 校验失败：在结果编辑框删除必填字段并保存，必须拒绝且无新文件。生成阶段若 JSON 结构错误，应只追加一次修复请求；二次仍错显示校验失败，不导出。
8. 暂停：生成中点暂停，网页可继续生成，但不能提交下一任务。点继续，应重新读取原绑定回答，不再发送原提示词。取消任务后不得导出；网页若继续生成请手动停止。程序重启后当前任务待人工处理，已完成任务不重发。
9. 登录失效/验证码/额度：仅在实际自然出现时检查 blocker 规则能触发暂停；人工处理后继续。不要制造绕过、换账号或反复重试。实际状态未出现则记录“未测试”。
10. XLSX：打开导出记录对应文件，Excel 无修复警告，Pages=8行数据、Menus=8项目，列名和顺序符合原样例，Published为true。检查 Contact Us 模板和 About/Information 菜单。修改后保存应新增修订文件，原文件不能变化；同一修订不重复导出。

只有这些实测通过后才能将该实验构建视为适合你的豆包账户和当前页面版本。请将失败步骤和界面错误反馈，开发者再针对实际结构修正，不能凭单元测试认定真实网页链路已通过。
