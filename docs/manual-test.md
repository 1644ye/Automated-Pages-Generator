# 由使用者执行的现场验收

开发者不控制屏幕。0.1.4 两轮真实协议已收到并分析；0.1.8 的后台调用由你实际测试。不要发送密码、Cookie 或整个浏览器目录。

## 0.1.8 后台连接测试

1. 关闭旧程序。解压完整 `Automated-Pages-Generator-0.1.8-win32-x64-experimental.zip`，运行其中的 exe，确认界面 v0.1.8。
2. 右侧手动登录，手动新建普通测试会话。点击「开始后台校准」。此时没有自动发送。
3. 点击「复制测试1」，在右侧手动粘贴发送，等待回复结束。再在同一会话发送「复制测试2」，等待结束；再发送「复制测试3」并等待结束。
4. 如出现「可以测试」，点击「测试一次后台调用」，观察状态。不要在右侧再发送内容，也不要切换会话。
5. 点击「结束并保存报告」，反馈界面的报告路径和错误提示。文件为 `%APPDATA%/automated-pages-generator/diagnostics/doubao-backend-*.json`。

需要重做三条消息的原因：0.1.4 只保留脱敏结构，没有存储请求真实参数；0.1.8 需在当前网页内存中学习参数关系与 patch 数值，并精确核验拼接正文。这不是你上次操作失败。

成功要求：三次手动校准完整匹配；单次后台测试的正文精确匹配；捕获到不同于三次手动请求的新签名。不满足则停止，不重试、不导出业务 XLSX。即使短消息通过，也不表示已完成长回答、联网或批量测试。旧业务任务保持暂停。

入口已含签名或动态参数无法建立实测关系时，后台按钮不会放行；请直接保存报告。登录、验证码、额度等由你手动处理。停止测试会清理内存模板与读取器，但已发到服务端的消息不能撤回。网页刷新使本次校准失效。

总观察5分钟，手动阶段4分钟，后台阶段60秒。报告只含状态和脱敏证据，不含正文、凭据或原始标识符；仅记录受限的消息序号数值。测试过程中不要同时使用原协议采集工具。

## 适配完成后的完整验收清单

以下用于后续生成链路验收，不是当前协议采集的操作要求。旧版 DOM 路径需先完成实际定位规则适配；后台直连若实现，应按相应版本说明测试。逐项记录通过/失败、错误信息和任务 ID。

1. 解压并运行 exe。左侧输入/队列/结果出现，右侧豆包可交互；在右侧手动登录。退出再运行，确认登录仍有效。
2. 使用旧版 DOM 路径时，根据 README 标定 input/send/user/answer/body/done/stop/blocker。重复容器采用通用规则，body/done 使用 answer 内相对规则。不存在的状态（验证码/额度）不要猜测选择器；在出现时手动确认并补齐 blocker。
3. 填写合成参考信息、折扣20，加入整条数据任务，点击检查并继续。确认网页只发送一次，任务标识一致，流式区域只显示对应回答。应得到七个生成页面和固定 Contact Us，About Us 至少3000词。
4. 检查长回答：滚动页面使旧消息离开可视区，再滚回，展开折叠。对照豆包复制出的完整回答与任务文本，不能缺尾或混入旧回答。当前虚拟化跨片段拼接未实现，无法绑定时应暂停/超时，不能导出成功。
5. 联网：标定真实 search/searchEnabled，勾选联网，选低风险公开资料任务。页面必须显示联网启用；保留实际来源 URL 并人工核对。关闭或删除联网状态规则时应拒绝发送，不得显示已联网核实。
6. 单字段：完成一条任务后点击它，在结果框修改 marketing.hero.description 为人工文字；只勾选 marketing.hero.title，加入任务。结果 title 更新，其余字段与手工描述必须逐字不变。页面 title 必须保持既有固定页面名。
7. 校验失败：在结果编辑框删除必填字段并保存，必须拒绝且无新文件。生成阶段若 JSON 结构错误，应只追加一次修复请求；二次仍错显示校验失败，不导出。
8. 暂停：生成中点暂停，网页可继续生成，但不能提交下一任务。点继续，应重新读取原绑定回答，不再发送原提示词。取消任务后不得导出；网页若继续生成请手动停止。程序重启后当前任务待人工处理，已完成任务不重发。
9. 登录失效/验证码/额度：仅在实际自然出现时检查 blocker 规则能触发暂停；人工处理后继续。不要制造绕过、换账号或反复重试。实际状态未出现则记录“未测试”。
10. XLSX：打开导出记录对应文件，Excel 无修复警告，Pages=8行数据、Menus=8项目，列名和顺序符合原样例，Published为true。检查 Contact Us 模板和 About/Information 菜单。修改后保存应新增修订文件，原文件不能变化；同一修订不重复导出。

只有这些实测通过后才能将该实验构建视为适合你的豆包账户和当前页面版本。请将失败步骤和界面错误反馈，开发者再针对实际结构修正，不能凭单元测试认定真实网页链路已通过。

## 0.1.8 消息序号校准

0.1.7的用户实测已通过两条短回答的完整解析，但尚未发送后台测试，原因是请求last_message_index不等于已观察的问答序号。0.1.8新增第三条手动校准，以连续两次实测转换检查固定值或与问答序号的固定差值；候选必须对下一序号给出同一结果，否则停止。不是硬编码加1。报告只记录0至1000000范围内的序号数值及关系，不记录消息ID或凭据。每次只允许一次后台短消息测试，业务队列仍未接通。
